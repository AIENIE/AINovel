## 复现工具的边界

研究脚本硬绑定本轮 runId 和数据目录，不能直接当通用产品功能；冻结和 seed 命令都拒绝覆盖已有状态。已停止的组不能继续调用。若未来另开研究，须新 runId、新目录、新预算和新的冻结协议，不删除旧记录重用额度。

离线重新核验现有产物：

```powershell
python -X utf8 scripts/research/slop3-client.py verify
python -X utf8 scripts/research/test_slop3.py
```

首次冻结顺序为 `slop3-freeze.py` → 编译/运行 `Slop3Prompts.java` → `slop3-freeze.py --seal`。Java 类路径使用已编译生产 `backend/target/classes` 与既有研究依赖；编译产物保存在忽略的 `artifacts`。当前交付已冻结，不应重跑生成覆盖请求。

在线 session 复用现有 SSO 表单/CSRF/授权码流程，正常 TLS 校验，凭据通过交互输入只在内存使用。每条 JSON 命令只派发一次请求。客户端无自动重试；HTTP 状态不明时先读取服务端账本，`reconcile` 只取回已完成且已结算结果，保留原传输错误。无记录、仍 STARTED、结算未知均阻断，不能自行重试。4 次重试额度只是上限，本轮未使用，也未提供自动消费备用额度的路径。

`slop3-export.py` 仅从本轮本地账本快照/响应导出，不联网；输出统计、提示 diff、原文阅读版和汇总不覆盖冻结输入。原始运行数据在忽略的 artifacts 中；可入库的完整请求/正文/费用在 `experiments.json`，运行时 env 不入库。
