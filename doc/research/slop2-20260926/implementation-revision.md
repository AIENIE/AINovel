# 下一阶段实施建议（替代第一轮中的质量假设）

这是待立项方案，本轮不落业务代码/数据库迁移。没有证据支持默认自动采纳。保留第一轮的安全编辑基础设施；把“检测风险下降→修一次→通过”替换为“确认问题作用→选操作→核对硬约束→作者决定”。

## 保留、替换、延期

保留统一正文抽取、全文覆盖清单、UTF-16 坐标、原句匹配、来源哈希/版本、异步任务/幂等、不可变版本与撤销、H2 隔离。规则库仍版本化，500 字窗口和12问题上限不变，SHADOW 不升级。

替换“删细节就是失败”为分级政策：硬约束是事件、知情/不确定性、否定、线索、物件归属和意图；冗余停顿、重复描写可删并，必须说明声音/情绪/节奏影响。可保护表达覆盖一般改写建议。模型不得凭“更顺”改事实，也不借编辑修原稿逻辑。

替换“更多句式规则就是质量”与“风格卡即个性化”。先审计画像来源、测量定义、样例完整性、角色归属与 H2 实际注入。风格卡仅描述目标表达，不承载事件事实。正向场景目标允许“不发生关系变化”，普通生活细节与新增重要往事有不同授权范围。

延期自动接受、跨作品偏好学习、专用编辑模型部署、SFT/偏好训练、参数透传与多候选产品；本方案不解除原 G2、H2、H3/H4 或题材分库门槛。

## 建议接口契约

扩展现有质量报告和 revision task 类型，不另建正文真相源。请求至少含：`manuscriptId/branchId/sceneId`、`expectedVersion`、`sourceHash`、`extractorVersion`、`mode=feedback|minimal|paragraph`、`preservationPolicyVersion`、`protectedRanges`、`contextStamp`、`idempotencyKey`。作者可声明要保持的声音/意象与本次表达目的，不能由推断自动永久入偏好。

响应：`coverage`（每块 UTF-16 半开区间、正文哈希、相邻上下文、完成/失败）、`issues`（原文证据、叙事作用、置信状态、可弃判）、`suggestions`（稳定 ID、关联 issue、原句 quote、start/endUtf16、replacement、delete/replace/merge/reorder/noop/feedback、理由、五维影响、事实核对证据与状态）。`no change needed` 与 `cannot judge` 分开。模型没有有效位置时只显示反馈，不允许自动猜引文。

应用接口提交选中 suggestion IDs 和 expectedVersion/hash；服务端在锁定当前分支版本后逐项校验 quote/范围、保护区、重叠和权限。多条接受先形成确定性执行计划，倒序应用；冲突整体拒绝并返回需重审项。正文变化后旧提案标 STALE，不能模糊匹配后直接应用。重复引文用范围+上下文定位，不靠第一次 indexOf。Unicode 不在代理对中间切分；前端富文本节点到纯文本映射保持版本化，归一化文本必须保留回映射。

任务状态沿用既有生命周期，提案追加 `PROPOSED/ACCEPTED/REJECTED/STALE/UNDONE`，失败区分 transport、budget、invalidPatch、hardConstraint、coverageIncomplete。接受/拒绝/撤销事件带 task/suggestion/source/result version、作者显式理由、时间。偏好仅从允许学习的事件派生，可删除；未点击不是反对或同意。

自动入口将来最多一轮提案：完整覆盖、有效补丁、硬约束全部有证据且通过、无声音退化时才具备评估资格；不确定、问题外新增事实、任何校验失败都保留原稿。原稿/修订稿/diff 持久化。即便具备资格，开关仍默认关闭，须独立真人与成本验证。手动入口可保留有争议提案供作者选择，但硬失败必须显著解释，不能显示为“安全”。

## 数据迁移建议

采用新 Flyway 版本追加列/表，不改历史迁移：质量报告追加来源/抽取版本、覆盖 JSON、政策版本与多维评价；revision task 关联不可变源版本；建议及处置事件可独立表，索引 task、source version、suggestion ID。旧报告标 `LEGACY_UNLOCATED`，只读展示，不伪造坐标或可应用状态。迁移只增加数据，不全量重评分/付费补跑。JSON schema 版本化；并发版本、过期和幂等收据需要数据库唯一约束。

保留证据全文的访问控制与原稿同级。H2 上下文 stamp 与事实问题只从当前可见投影取得；作者秘密不可借“事实检查”交给场景写作模型。评审源事实与角色已知事实分别标注，不把全知核对答案塞进对白生成。

## 验收矩阵与启用条件

| 层级 | 必须验证 | 通过标准 |
|---|---|---|
| L2 提取/位置 | 重复引文、emoji/扩展汉字、CRLF、组合字符、富文本多段、空段、长正文尾部 | 全文覆盖可证明，位置回映原句；不静默截断、不拆代理对 |
| L2 应用/状态 | 重叠补丁、合并/调序、保护区、版本冲突、幂等重放、失败恢复/预算耗尽 | 冲突不覆盖，失败可恢复且不重复付费，原稿始终可还原 |
| L2 内容政策 | 否定、可能→确定、人物知情、物件归属、关键尾段、意图改变；可删光标停顿；口头禅与意象回扣 | 硬失败拒绝；软变化不自动失败；声音损失独立报告；复核必须覆盖每个 diff 操作而非仅回答问答 |
| L2 上下文/风格 | H2开启/关闭、角色切换、样例边界、超长画像、未授权秘密诱饵 | 实际请求与预览一致；来源可解释、样例不半句截断、秘密不泄漏 |
| 本地 L4 作者流程 | 真实 SSO→诊断→只反馈/提案→逐项接受拒绝→撤销→刷新；桌面/窄屏；跨场景/跨分支切换 | 无旧提案错套，无丢稿；作者能看原文差异和恢复版本 |
| 本地 L4 负路径 | 调用中改正文、超预算、上游失败/超时、重启、任务重复提交 | 费用与幂等核对一致，未确定结果先对账，不自动重试追分 |
| 质量启用 | 独立中文真实作品与作者分组留出；不修改基线/反馈/最小补丁对照；五维判断 | 零硬约束失败、多数明确收益、无系统性声音退化；作者接受耗时/撤销率可接受，公布样本规模与不确定性 |

本轮仅执行研究工具和本地真实 API 对照，不把上表写成已通过的产品 L4。后续先开展作者确认的小范围建议模式，记录每千字问题数、误报/漏报、弃判、采纳后撤销、审阅分钟数和表达分布漂移。多样性要比较同题材/同长度/同作者基线，避免长度或稀有词把分数抬高。
