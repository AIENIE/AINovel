# 检测离线对照与反例

72 条冻结片段为 48 开发 / 24 留出，六类各12条、各半需修改/需保留；同一源场景与其变体同集合。旧24条降为历史回归资料，不能再称未知留出。

来源仅6条真实输出摘录、6条受控追加、60条代理构造。真实摘录全部标为可保留，因而**真实自然问题的召回率不可估计**。留出24条全为构造，设计者与原型作者为同一代理，虽然没有按留出分数调参，仍存在设计耦合，不能视为独立未知泛化测试。正反例标签也是代理判断。

基线使用现有 `LocalSlopHeuristics.requiresAiReview`，比较的是“是否触发复核”，不是逐 issue 分类或模型诊断准确率。原型是手写词法归一/重复骨架和500字符窗，非句法解析器；原型只读，不修改生产500字窗、阈值、12问题上限或SHADOW状态。

数字看似“零误报”，只在这批标签上成立。原型只声明候选观察；以它直接要求修改，则另做的9份旧全文挑战中，fast:1 命中3次“不是”，实际分别区分浆糊来源、线结用途及旧照片证据，是有信息增量的推理。代理判这一窗口不应因形式删除。其余8份无信号，不代表无质量问题；没有给全文完整真值，因此不计算全文精确率/召回率。记录在 `corpus-structural-observations.json`。

`offline-metrics.json` 的历史字段 `abstentionRate` 实为**未触发率**（基线66/72，原型40/72），混合真阴性与漏报；本轮没有真正显式弃判分类器，弃判率应报“未实现/不可估计”，不能拿未触发率当不确定性校准。未来应返回 issue/noIssue/uncertain 三态并为 uncertain 单独标注原因。

逐例输入与标签见 `samples.json`；当前完整 issue 输出见 `baseline-results.json`；观察信号见 `structural-results.json`。原型漏报主要在抽象总结1例与节奏3例；这要求新的证据与作用标注，不能看到漏报后继续把本留出集调成开发集却仍称未知。

跨段复用、同义信息重复、句长/停顿分布是后续观察维度，本轮未实现语义去重或完整依存句法，也没有部署训练模型。短窗口不能替代章节层主题/意象追踪；建议下一步按作者标注“信息增量/声音/回扣/无功能重复”而非仅正则命中收集数据。
