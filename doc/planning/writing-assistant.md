# 写作 AI 助手：长期设计与分期实施约定

本文保留 2026-10-13 正文助手一期的实施约定，并记录 2026-10-15 批准的故事级讨论与资料提案一期。分期状态、优先级及前置条件只在[路线图](../roadmap.md)维护，不在本文建立第二份状态账本。

## 产品目标与调研结论

助手成为写作工作台的自然语言操作入口：理解作者正在处理的正文，按需获取证据，交付可比较、可继续修改、可采纳的结果。作者掌握正式正文和故事事实的最终决定权。

原有 Copilot 只有组件内聊天历史；前端虽发送当前正文和场景摘要，后端模型调用仅转发 messages，没有装配 context。原编辑器润色与续写也各自调用模型。新的助手采用独立上下文装配、持久回合和编辑提案，共用现有任务、保存和版本基础。

| 能力方向 | 作者请求示例 | 交付与收益 | 成本和边界 |
|---|---|---|---|
| 当前正文修改 | 争执写得自然一点，保留最后决定 | 选区/场景修改提案、差异、采纳 | 一期；富文本定位、版本冲突和恢复是主要工程成本 |
| 前文查找与问答 | 他在哪一章知道这件事 | 带出处原文、定位及不确定说明 | 一期；确定性检索，不能声称读懂未检索到的全书内容 |
| 候选继续打磨 | 保留上一稿对白，压缩叙述 | 新候选和父稿关系，原稿仍可比较 | 一期；新回合有新用量，不覆盖旧候选 |
| 现有工具编排 | 比较版本，解释语言诊断 | 统一发起已有任务并解释结果 | 后续；逐项接入已验收能力，不复制质量链路 |
| 创作资料整理 | 把讨论整理成角色卡建议 | 可审阅的角色卡、章节和场景大纲提案 | 故事级一期；世界设定写入保留后续，聊天设想不是正式事实 |
| 跨章修改 | 改职业并找出受影响章节 | 影响清单、分场景提案、分项采纳 | 较高成本；对应 H4 等方向，另行确认依赖与验收 |
| 长期创作协作 | 安排伏笔推进、在草稿分支续作 | 分阶段规划、生成、核对与作者确认 | 长期方向；对应 H3–H6，不解除当前门槛 |

## 正文助手一期确定的体验（2026-10-13）

范围为当前场景或连续选区，读取相关内容后回答、澄清或提出一份修改；作者先审阅完整差异，再整体采纳保存。支持普通段落增删拆合。标题、列表、引用、代码和其他固定结构保持，不跨固定结构合并。跨场景只读，不修改大纲、角色卡或账本。

按稿件/分支/场景持久化会话；关闭、刷新、桌面/窄栏/移动切换可恢复。每回合绑定原文、选区、指令及可选父提案。完整历史留存，送模最多最近八个符合本回合用途的回合；预算不足先省略旧对话并说明。候选继续打磨产生新回合/新提案，未采纳时沿用最初原稿基线，已采纳后改用当前正文。

普通模式允许未保存草稿；H2 发起前须明确保存成功，再冻结正文和原有上下文版本戳。等待期间允许继续编辑，新编辑使旧提案不可直接采纳。H2 改稿只使用受控 SCENE 的 content/included，excluded 原文及广泛作者问答历史不进入改稿。需要新知情信息时走既有作者确认入口。

提案展示实际读取来源、未读范围、完整前后正文、细粒度差异、段落变化、汉字数和篇幅差额。越界可明确采纳，不触发隐藏的长度修订、诊断或质量复核。支持拒绝、保留、继续打磨。正文润色和续写入口迁入助手；其他聊天/润色消费者保持兼容。

## 有限编排与数据约定

每回合最多两次模型业务调用：首次可直接交付，或提出一次最多四项只读查询；查询直接返回可引用摘录，然后第二次交付回答、澄清或提案。不循环查找，不自动修复非法模型格式。补充上下文合计 3500 estimated-token，完整目标正文、指令和父提案仍纳入现有请求限额；不扩大预算，不截断正文结尾。确定性检索不调用 embedding/rerank。

继续使用当前模型和网关文本接口。原生工具协议虽已存在，但当前契约仍标为待部署且客户端未接入；一期不以此为依赖。业务读取与提案接口可供将来替换调用适配器，当前不引入代理框架。

新增 session、turn、proposal 三类记录及 WRITING_ASSISTANT_TURN 异步任务。回合冻结正文、选区、目的、来源和每步精确请求/回执；提案持久化前后正文、父提案、来源版本及处置回执，不能冒充 generation 候选。下一空闲 Flyway 编号当前为 V37，不修改 V1–V36。

每步发送前独立保存请求和稳定调用标识；完成结果立即落库。恢复原任务不重新检索或换键推理；用户主动重做创建新任务。结果不确定保留原对账状态，取消保留已完成成果但不继续外发。任务完成与正文保存明确分开。

接口位于稿件/场景 assistant 路径，提供分页会话、提交回合、回合详情、提案详情和 accept/reject/undo。提交和处置均幂等；同会话有任务时，新指令明确返回忙碌，不能复用旧任务吞掉请求。

## 富文本与保存

服务端将连续顶层普通段落划成可编辑组，基于冻结选区生成组 ID。模型只返回组 ID 和字符串段落数组；首尾非选中切片由程序保留。未改变文字保留原格式，变更文字只继承明确共有标记，新段为普通正文。服务端从原文独立构造最终 HTML；前端不上传任意 afterHTML 作为采纳结果。新增 jsoup 1.23.2，前端复用 TipTap，不改变历史 LanguageProjection 契约。

采纳进入现有稿件写队列，停止目标待触发自动保存，等待在途请求，并核对本地草稿。普通模式必要时先保存作者基线；严格保存原语必须返回真实回执或抛错。原稿已保存而采纳失败要分别报告。采纳事务检查版本/分支/原文及上下文，保存正文、前后快照、编辑归因和处置回执，不执行 AI 检查。

撤销只恢复目标场景，要求当前正文仍等于本次采纳后的正文且分支一致；否则提供比较和版本入口，不覆盖后续编辑。不自动三方合并。

## 故事级讨论与资料提案一期（2026-10-15）

### 讨论与显式整理

故事级入口服务于构思、角色设计和章节场景编排，不依赖稿件或正文场景。每个故事可新建并手动命名多个话题，保留最近使用的话题；刷新或切换工作台标签后恢复对话。话题跟随故事，不跟随稿件分支。当前选择的故事和单个目标大纲必须清楚展示，避免把共享资料误认为某个正文分支的私有修改。

普通讨论只回答和提出整理建议，不写角色、大纲或正文。助手可随同本次答复提示“整理为角色卡/章节场景”，提示本身不另发模型请求；作者点击整理才创建新的异步任务与用量。作者也可主动整理当前讨论，或继续打磨已有提案。多个备选方向先保留在讨论中，一期不建设多方案竞技场。

上下文为当前故事资料、角色卡、作者选定的一个大纲和当前话题的相关讨论；不默认摄入全书正文，不跨故事搜集资料。无大纲时仍可讨论、整理角色卡；章节场景提案须先选择目标大纲。话题、来源和候选均持久化，关闭面板不丢失已返回结果。

### 提案、冲突与撤销

提案分为角色、章节、场景三类，每项明确新增或更新；新章及其首批子场景作为一个不可拆项。作者逐项审阅字段前后变化，可手工编辑候选再采纳，不自动整包落库。更新既有资源保留身份和未涉及内容；新增章节只追加到大纲末尾，新增场景只追加到所属章节末尾，不删除或重排现有内容。

整理和采纳前，目标资料若有未保存编辑，须先保存成功或取消该编辑。候选基于冻结的目标内容；目标已被改动时明确报告冲突，不覆盖新值、不自动合并。某项冲突不阻止其他仍适用的项目逐项采纳。采纳写入现有角色卡及大纲实体，刷新后可在原编辑页面继续维护。

新增项采纳后不提供自动撤销，作者通过原有编辑入口管理已创建资源。更新项仅在当前目标仍等于本次采纳后的内容时允许撤销，恢复原目标；后续编辑使撤销不可用。采纳、拒绝、手工编辑候选和撤销均不调用模型。重复提交及处置复用原回执，不能重复创建角色、章节或场景。

### 生成消费与已有边界

普通场景生成继续通过现有编译器消费保存后的角色资料与整体/章节/场景 planning；资料提案不另建事实库。H2 继续只消费其既有作者确认的本场计划、适用背景和人物可用表述：采纳角色卡或大纲不等于新增人物知情，不自动转换为 H2 PLAN、BACKGROUND、知情记录或 H1 正式账本。

故事级讨论属于作者视角，不把其广泛资料或历史注入 H2 正文编辑。H2 的来源、顺序、依赖和版本失效保持原机制；大纲保存沿用领域事件，角色卡保存不承诺自动重写或全面失效旧知情记录。需要新的 H2 计划或知情时，由作者使用既有确认入口完成。

### 任务与验证交付

复用当前模型、AI 网关和异步任务基础。单次讨论、整理或打磨任务至多两次模型业务调用、一次最多四项确定性只读查询，不使用 embedding/rerank，不增加自动格式修复或循环规划。冻结输入、每步请求、稳定调用身份和回执；恢复原任务沿用原资料及请求，不重新取当前资料替换旧输入，不换键重推未知结果。新任务和新用量明确区分。

工程验证不代替真实讨论、提案质量、可见页面和文学效果。H/G 阶段状态、SCORE 与其他未完成验收继续保留；后续能力仅登记到现有路线图的候选分组，不进入执行队列。

## 安全事项

无新增或调整的独立安全策略，无额外安全扫描。沿用资源归属、分支版本、H2 隔离、任务执行、幂等结算及不确定结果对账；业务读取不扩大作品访问范围，正式正文或故事资料由作者采纳写入。故事级讨论不改变 H2 输入准入、作者确认和历史隔离策略。上述机制不保证文学质量或完全保留原意。开发及回归成本包含在各期范围内，无新增独立部署组件。
