# H1 — Plan 1：Direct implementation

当前状态只见 [路线图](../roadmap.md)。本期使作者把认可的场景正文转成可追溯、可纠正的状态；不接入生成、全书导入、完整因果推理、伏笔图或自动改稿。

## 数据与事务

`story → manuscript → branch` 是隔离范围，同故事的不同稿件不共用账本。V15 新增分支账本、正文确认、抽取批次、状态记录、提交历史五张表；V1–V14 保持不变。`canonRevision` 与稿件乐观锁、正文快照 ID 独立。

确认保存后的正文时固定 `V2ManuscriptVersion`、服务器归一化文本块、内容哈希、章节场景顺序、确认人和时间。被引用快照标记保护，不参与自动清理。证据按 Unicode code point 定位；模型只提供块与引文，服务器要求唯一精确匹配并重算位置。展示使用不可变纯文本，不把历史坐标套到可编辑正文。

抽取仅接收确认场景、人物 ID/名称，以及披露位置在本场之前的有效账本记录。人物简介、大纲内容和 Lorebook 不进入输入。每条候选区分 FACT、UTTERANCE、BELIEF、RUMOR、INFERENCE；信念要求持有人，故事内时间可未知。证据格式校验不证明语义正确，梦境、反讽、传闻均须作者判断。

确认与任务创建在同一事务完成。`NARRATIVE_STATE_EXTRACT` 复用 `AiOperationService`；P11 提示词固定版本，调用 `AiService` 的 `NARRATIVE_EXTRACTION/extractionId/p11-v1` 幂等计费上下文。每批只调用一次模型，不追加修复调用。格式错误、部分候选无效、零候选、取消及上游失败分别处理；重试复用已有调用记录，已保存业务结果不重复解析或调用。

作者一次提交全部候选的接受/拒绝（接受可含修改），以及补充记录；校验完成后原子提交，保留原候选和审阅。写入前再次检查权限、当前分支、正文版本、账本版本与来源。幂等键绑定请求哈希，重放先返回持久化回执。默认追加；替代必须由作者指定同分支有效记录。未提及不会删除。

保存、生成写回、回滚、合并、质量修订采用和大纲变动触发来源核验；读取与写入时另有核验兜底。正文纯格式变化不使证据失效；内容、删除、位置前缀变化和已记录输入依赖变化会标记待复核，并保留历史修订查询。恢复原文不会自动恢复已失效记录。新分支空账本；合并只影响目标正文，不导入来源状态。H1 只追踪来源和实际消费记录，不宣称发现所有跨章因果影响。

## 界面与兼容

桌面与移动工作台共用“证据与状态”面板，区分待审阅、已确认、待复核，支持历史证据、任务取消/恢复和审阅草稿刷新恢复。未保存时禁用抽取。确认正文不等于接受结论或发布作品。

旧稿不自动建事实；旧角色变化触发器返回 `501 ANALYSIS_NOT_IMPLEMENTED`，历史日志只读且返回 `UNVERIFIED_LEGACY`。H1 不改动既有 36 个质量 fixture。

## 验收契约

1. L2：新增文本/持久化/任务/界面测试，受影响测试后执行前后端完整单元测试、类型检查、lint 与构建。
2. 证据：准备不等于获得、发言不等于事实、误信纠正、梦境/反讽/未知时间人工确认；中文、生僻字、emoji、实体、重复引文、纯格式变化与快照保护。
3. 权限与版本：重复请求、并发版本冲突、抽取中改稿、跨用户/稿件/分支、回滚、合并、删除重排、依赖传递与历史查询。
4. 故障：超时、取消、重启恢复、格式错误、无变化与计费重放，不产生部分有效记录。
5. L4：Windows 标准启动与真实 SSO，自有测试正文，不超过六次真实抽取；走通确认、候选修改、入账、证据、旧稿修改、刷新和分支隔离，检查桌面与窄屏可见结果、控制台和失败请求。

真实 AI 语义错误及人工修正与离线测试分记；外部环境阻塞时保持验收中。API 与操作步骤见 [接口](../api/v2-narrative.md)、[用户指南](../../user-doc/12-证据与状态.md)。
