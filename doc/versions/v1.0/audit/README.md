# AINovel v1.0 安全与稳定性审计总报告

审计日期：2026-09-26。基线：`develop` / `2a1fb98a9e85d9de9feee6e2d820ce7961797a82`，包含审计开始时已有工作区改动。目录中的 v1.0 是本次文档归档位置，不代表已发布某个版本。

## 审计结论

项目已有鉴权隔离、版本冲突保护、任务幂等键、有限队列、迁移和自动化测试基础，但仍存在应优先修复的正文完整性、异步任务状态一致性和资源占用问题。尤其是跨稿件缓存污染已被真实 React hook 的隔离测试复现，中文 PDF 输出也存在确定的字符损坏。现有测试全部通过不能作为这些问题不存在的证明。

三个方向共形成 **23 项专题发现**，每项都有代码位置、触发条件、影响、修复建议及关闭验证方法。该数字不是 23 个安全漏洞，也不表示 23 项均在生产环境复现。依赖公告、静态确认、条件性风险和动态复现分别标注。

| 审计方向 | 报告 | 发现分布 |
|---|---|---|
| 代码安全 | [代码安全报告](code-security.md) | 6 项：高 2、中 3、低 1；两项高危均为依赖命中，实际利用具有额外条件 |
| 代码性能与稳定性 | [代码性能与稳定性报告](code-performance-stability.md) | 9 项：P1 4、P2 5；含 1 项已动态复现的串稿问题 |
| 代码易读性及可维护性 | [代码易读性及可维护性报告](code-readability-maintainability.md) | 8 项：P1 1、P2 5、P3 2 |
| 验证与证据 | [验证记录](verification.md) | 实际命令、测试结果、条件跳过、工具链补验与证据入口 |

安全报告的高/中/低表示安全影响级别；其他报告的 P1/P2/P3 表示整改优先级。它们不能直接当成同一种 CVSS 分值相加。P1 表示优先处理；P2 表示应计划修复的具体问题；P3 表示较低优先级的维护改进。发现被标为“条件性”不等于已发生事故。

## 优先整改清单

| 顺序 | 对应发现 | 应得到的结果 | 关闭证据 |
|---|---|---|---|
| 1 | PERF-01 | 切换稿件后草稿、定时保存、在途保存与当前稿件身份保持一致 | 同场景 ID 的 A/B 稿件、切换时在途请求与切回未保存草稿的回归；本次复现测试应改为隔离行为断言 |
| 2 | MAINT-01、MAINT-02、MAINT-03 | 中文导出完整；错误合并参数和损坏存储输入不得静默覆盖正文 | PDF Unicode/分页回读及渲染；未知策略/null 的 4xx 与数据库不变；坏 JSON 写入事务回滚 |
| 3 | PERF-02、PERF-03 | 取消不可被旧回调复活；同一任务只有当前合法执行者可应用结果 | 可控并发、旧 attempt 晚返回和数据库双领取竞争测试；多实例风险须在扩容/重叠启动前关闭 |
| 4 | SEC-01、SEC-02、SEC-06 | 相关已知依赖漏洞被处置，PNPM 及最终后端产物审计有真实门禁 | 新锁文件/产物扫描、兼容回归、扫描失败不生成 passed；开发服务暴露面单独验证 |
| 5 | SEC-03、SEC-04、SEC-05 | 本地管理员能治理，普通用户不能自改审核结果，孤立任务仍有所有者边界 | 真实过滤器与服务链的授权正反例；素材删除后的他人任务查询被拒 |
| 6 | PERF-04、PERF-05、PERF-08 | 模型等待不持业务事务/用户行锁；索引不阻塞共享调度；慢下载不长期占数据库连接 | 延迟 stub、受控慢客户端与连接池/锁/调度指标；按实测结果确定资源预算 |
| 7 | PERF-06、PERF-07、PERF-09 | 长篇保存、后台列表和查重的工作量有明确规模边界 | 场景级读写、数据库分页/投影、候选上限及代表性数据规模验证 |
| 8 | MAINT-04–MAINT-08 | 网络与正文契约明确，迁移测试可信，接口/入口文档一致 | 畸形 DTO 边界测试、共享正文语料、受控 MySQL 迁移、生成 OpenAPI 与文档一致性检查 |

整改顺序是技术建议，不设未经确认的负责人或期限，不自动启动路线图中被门槛阻塞的功能。涉及现有 Slop/H2 正文契约的改造仍应遵守 `doc/roadmap.md` 的优先级与验收要求。

## 本次验证结果

- Windows 标准 L2 入口成功；后端编译打包通过，**392 项测试通过、17 项条件跳过，零失败/错误**。
- 前端最终使用仓库要求的 **Node 22.23.2 / pnpm 11.22.0**，lint、类型检查、生产构建、**40 文件/169 项测试全部通过**。首次误用系统 Node 24 的结果已明确记录，并完成匹配版本补验。
- 隔离串稿测试 **1 项复现成功**，使用真实 hook 与模拟网络，不读取真实稿件。它证明缺陷存在，并非修复验收。
- 前端依赖审计返回 **55 条命中**（Critical 1 / High 27 / Moderate 26 / Low 1）。安全报告已解释开发工具利用前提、包/公告重复与生产可达性的区别。
- 已检查最终后端 JAR 中的依赖版本；尚未完成全部 Maven 组件的漏洞关联。未将一项公告核实冒充全量依赖清零。

验证记录保留每项跳过测试的来源。条件跳过的真实 MySQL、容器迁移与研究验证均不算通过；后续修复不能只依靠当前全绿的默认测试集关闭问题。

## 范围与交付边界

审计覆盖前端、后端、数据模型/迁移、异步处理、依赖与脚本，并阅读相关架构、API、验证和路线图文档。范围盘点包含 465 个后端生产 Java 文件、121 个后端 Java 测试文件、206 个前端 src 跟踪文件（含测试/语言资源）、18 个 Flyway SQL、55 个 scripts 跟踪文件。三个 agent 沿各自重点调用链深入检查，主审交叉核对高影响结论；这些统计不是逐行审阅覆盖率。

本次审计交付内容全部位于本目录：总报告、三个专题报告、验证记录与 `evidence/` 下的扫描/复现证据。常规验证同时产生了被 Git 忽略的构建产物和本地日志。未改业务代码、依赖锁文件、既有用户改动或路线图，未提交 Git。

未执行部署、生产渗透、真实数据库操作、付费模型调用、浏览器 L4、压力测试、实际网关/TLS/系统矩阵运行态验证。报告可作为整改和复测依据，不能据此宣布生产环境已安全、满足容量 SLA，或 H/G 系列验收已经完成。
