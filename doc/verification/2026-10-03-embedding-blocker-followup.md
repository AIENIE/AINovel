## 已实施的本地修复

- 在关键词检索后，只有存在当前用户可见、已审核且版本匹配的素材片段才进行 embeddings 与向量检索。使用 `EXISTS`，不用整库加载或缓存跨用户结果。
- 语义检索失败仍返回关键词结果；日志只增加异常类型、gRPC code、白名单 HTTP status，不记录查询、正文、密钥或原始异常消息。可以识别“上游 401 后降级”，避免静默失去诊断线索。
- 修正旧测试名称及无效模拟：旧四参数构造器走纯关键词兼容实现，从未触发所谓向量失败。新增使用生产构造器的 401 降级测试，以及无可见素材时不调用远程依赖的测试。
- 没有更换 embedding 模型、重建向量集合或改变公开接口。

## 供应商配置修复方案

优先修复 API 3 的现有路由：在正式 AI 服务管理界面核对令牌所属站点、有效状态及模型权限；`.com` 端点使用 `.com` 令牌，若原令牌实际属于 `.cn`，在确认后将该路由改为匹配的站点。失效令牌需要受控更新。保留模型 ID、路由 ID 和模型语义，使用管理流程的加密存储及审计，不直接写数据库。

先用非生成式模型清单验证认证恢复及目标模型可见；然后在明确批准的调用预算内验证一个最小 embeddings 请求及正文流程。该修复依赖有效令牌或其所属站点信息，401 本身不能提供这些信息。此轮没有擅自更换共享凭据。

不建议直接把默认模型切为 Zhipu 以掩盖 401。不同 embedding 模型生成的向量空间不能混用，即使维度相同也不代表可比较。若选择替换模型，应显式固定模型与索引版本，创建对应集合，重建已审核素材索引后切换查询；这涉及额外共享配置和真实调用，不纳入本次小修。

素材已存在时，现有关键词降级可保住正文链路，但匹配范围和召回质量低于语义检索。后续可考虑把降级状态显示给作者、显式配置 embedding 模型和增加短时故障抑制；不能以此宣称供应商认证已修复。
