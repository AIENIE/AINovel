# H2 加固与 H3 门槛验证（2026-09-22）

结论：**H2 验收中；H3 未启动**。本轮修复已落地，输入隔离、完整长度修正、事务预算和真实落库追踪通过所列检查；小说输出仍会为误信补造关键来历，未达到无严重核心设定失真的门槛。没有实现 H3/V19、H4–H6，也没有部署。原《明日来信》及历次原稿保留。

## 实现与接口

- `Assertion.knowledge[].view` 与 `Document.grants[].view` 新增作者确认的 `{content, kind, certainty}`。类型保持原陈述；可信度限定为观察、转述、相信、推断或未知。作者陈述、纠错说明和原引文不发送给严格人物视图；全知视图仍分别标识叙述事实与人物知情。旧记录不自动复制原字段，缺失 view 排除，界面提示免费补充。
- 人物属性模板只把选定称谓、代词、外观整理成限定人物和场景的 BACKGROUND，不放行整张人物卡。缺失关键属性要求使用姓名，不自动补性别/身份；这项指令尚不能保证模型完全遵守。
- H2 长度修正携带完整上一稿、原结尾与冻结上下文；放不下时在调用前明确拒绝。初稿加最多一次长度修正，两次不达标保存 `LENGTH_REJECTED` 稿件并报错；不破坏现有正文。旧流程保持兼容。
- 预览增加 `promptVersion`。保留候选增加提示词/上下文哈希、模型和尝试次数，生成历史同样记录分支、正文、账本、配置、开关修订。真实请求与历史均已核对，不回填伪造旧历史。
- 本轮 `AI_VALIDATION_MAXIMUM_CALLS=200` 配合独立 `run-id` 和数据库行锁/独立事务计数，重启及失败不返还次数。配置高于 200 拒绝。旧 6/6 预算不复用。附带付费诊断/修订保持关闭。
- “质量门禁通过”改为“文本检查通过”，本地规则说明明确要求作者继续核对人物知情、剧情和设定，避免表层检查被理解成语义验收。

接口仍在既有 narrative API 下，期望版本与幂等键不变。新增字段存入现有 V18 JSON 修订，没有新迁移。H3 接口/分支修订号/迁移均尚未实现。详见 [H2 接口契约](../planning/narrative-h2.md)。

### 硬阻塞：误信的来源与归因仍会被模型补造

1. 工作台 v2 原稿第6段：**“信早烧了，是她亲眼看着火苗卷上去的，灰都清干净了。”** 原文只说她望着空信封而认定烧毁，实际信被沈河藏起；输入已过滤作者纠错，保留 BELIEF/BELIEVED，模型仍编造目击。这不是数据库把 BELIEF 改为 FACT，是输出对类型边界不忠实。
2. 冻结 A1 新版 FAST 长度修正第5段：**“已经烧过了。他记得自己确认过，确认过就算完了。”** 完整旧稿与结尾确实传入，修正仍把不确定信念补成确认经历。修复截断解决了软件缺陷，没有解决输出语义问题。
3. v3 工作台定向复验第5段：**“她相信自己已经把它烧掉了”**。禁止补造亲历的指令去掉了原来的火焰目击，却新增“本人烧信”的关键信念；与作者仅批准“信烧掉”的内容不相同。约束有局部效果，不能宣称问题已消除。原稿保留，账本没有因生成自动更新。

## 按优先级排序的建议

| 优先级/分类 | 问题与影响 | 后续建议（本轮未自动实施） |
|---|---|---|
| P0 文本质量 | 信念被补造获知过程、行动者或确认经历，破坏核心误会 | 继续留在 H2，先讨论在作者审阅中明确“陈述内容、依据、允许新增的归因”边界；只把作者确认的限制注入，不能凭纠错事实反推人物不知情。冻结新的独立验收前不继续调旧验收样本 |
| P1 软件反馈 | 本地规则低风险不代表语义安全 | 已改清提示；维持作者核对，不增加 H4 自动审稿、不自动接受账本 |
| P1 输入不足/表达边界 | 严格排除未分类文本后，地点、时代、称谓不足，模型容易自行补全 | 作者用已实现的范围条目补足明确地点/代词；不重新放开整个梗概或人物卡，不把“未提供”自动解释为“不知道” |
| P1 文本质量 | 限知场景断言他人想法、因果来源 | 已加输入指令，仍需原文核对；不能以指令存在替代效果验证 |
| P2 文本质量 | 收拾/擦拭动作过密、开篇平淡、末尾反复决定以后再说 | 用本场目标和选择代价减少纯程序动作；属于作者计划改善，不能靠多次无约束重写挑成功稿 |
| P2 文本质量 | 范围与指代不稳定（修船篷变换底板、手帕与伤口混指） | 逐段标出动作对象与任务完成条件；案例建议先保留，暂不建立 H4 自动逻辑系统 |

下一步需要讨论的是 H2 的输出边界与新独立验收，而非给 H3 开绿灯。200 次上限保持不变，不部署、不批量追加评测，不解除其他门槛。
