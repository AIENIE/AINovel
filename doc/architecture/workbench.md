# 创作工作台

## 入口与标签

工作台路由为 `/workbench?tab=<tab>&storyId=<storyId>&outlineId=<outlineId>&manuscriptId=<manuscriptId>&sceneId=<sceneId>`，入口文件是 `frontend/src/pages/Workbench/Workbench.tsx`。旧 `id` 参数只用于兼容历史链接，进入后会规范为 `storyId`。

| tab | 当前职责 |
| --- | --- |
| `conception` | 一键构思故事与角色草稿 |
| `stories` | 编辑故事卡和角色卡，进入故事级讨论与资料提案 |
| `outline` | 管理章节、场景和世界观引用，讨论并审阅选定大纲的资料提案 |
| `writing` | 正文、生成、质量、版本、导出、统计和目标 |
| `search` | 检索素材片段 |
| `lorebook` | Lorebook、实体和上下文预览 |
| `graph` | 图谱查询与关系维护 |
| `analysis` | 长篇 drift 巡检 |
| `v2` | 当前 v2 API 的联调与结果观察 |

## 正文与生成

- 桌面端为大纲树、编辑器、右侧工具三栏布局，支持多场景标签、自动保存和专注模式。
- 指定场景生成使用 `mode=fast|crafted`；`crafted` 注入分类反套路约束和轮换叙事目标。
- 达标自动保存后加载质量记录；未达标通过“生成候选”入口交作者审阅。任务成功不再一概表示正文已保存。
- 成功生成还会原子写入内部 `generation` 版本与场景生成记录。人工编辑提交后，以独立事务先保存待重算标记，再按 Unicode code point 精确计算；计算失败不影响作者正文，后续查询会通过正文 hash 漂移重试。重新生成和版本回滚分别保留 `SUPERSEDED`、`REVERTED` 历史。
- 服务端生成或候选修订写回时会取消目标场景待执行的自动保存，仅在目标场景没有未保存编辑时替换，并保留所有未保存场景，避免旧空正文覆盖生成结果。
- 前端把缺失目标 section 或仅含空编辑器 HTML 的生成响应视为失败。
- 提示词装配将稳定规则放在 system 消息，将故事、场景、角色、前文、素材和重试说明放在动态 user 消息。
- 场景起草使用版本化的 `scene-draft-v2` 上下文编译器：在固定 3500 estimated-token 预算内统一装配 planning、绑定世界、激活风格/相关角色声音、跨章最近正文、按当前场景锚点匹配且已启用的 Lorebook、两端条目均已入选的图谱关系和最多两个历史锚点，并为实际输入生成不含正文的来源 manifest 与 SHA-256 hash。
- G2 fast/crafted 样本对共享同一次上下文编译结果；V2 context preview 在提供 `manuscriptId + sceneId` 时复用同一编译器，未提供时保留旧 Lorebook 预览行为。
- 素材检索最多装配 8 条片段；向量能力不可用时保留关键词检索。

## v2 能力

- Lorebook、图谱关系、风格画像、角色声音、版本与分支、导出任务、模型偏好、布局、会话、目标和快捷键均持久化。
- 所有资源访问复用 `ResourceAccessGuard` 与领域所有者校验。
- 前端 API 统一位于 `frontend/src/lib/api-client.ts`，接口详情见 [`../api/README.md`](../api/README.md)。
- 导出下载通过带 Bearer 的 Blob 请求完成，桌面和移动端共用同一鉴权与错误处理链路。
# v1.0 审计整改补充（2026-08-17）

- 编辑器保存携带稿件乐观版本，冲突不会静默覆盖其他标签页或设备上的更新。
- 通用 AI、G2、导出、素材索引均以数据库状态和租约为权威；线程池拒绝或进程重启后由 dispatcher 恢复。
- G2 fast/crafted 候选独立持久化；恢复时只补缺失候选。通用 AI 已产生流式输出的异常任务进入 `RECOVERY_REQUIRED`。

## 篇幅候选

桌面、内置浏览器窄栏和移动布局共用顶部“生成候选”入口，关闭任务面板或刷新后仍可按稿件/分支/场景查询。列表只取摘要，选中后读取完整正文；另一稿到当前稿的保守差异保留全部文本，中间变化块可能包含未修改片段。两稿并列审阅，不按字数评判文学质量。

正文汉字数、目标范围和中点差额与累计输出 token 分开显示。起草、篇幅修订 1/1、待作者确认分别对应实际阶段。重新生成明确提示新用量，并创建新请求；恢复保留旧任务身份。

未保存编辑阻止主动采纳/载入；生成期间的编辑也不会被返回值覆盖。历史恢复稿载入后暂停该场景自动保存，直到作者手动保存。来源不完整不会补造上下文或质量结论。

## 写作助手

助手按稿件、分支和场景保存对话，统一正文选区润色和续写入口。普通模式从当前编辑草稿冻结输入；H2 先确认保存成功再冻结受控上下文。对话中的修改提案独立持久化，生成不修改编辑器，作者采纳才进入现有稿件保存队列。等待期间继续编辑会使旧提案不可直接采纳，不能覆盖新输入。

每回合至多两次模型调用及一次最多四项确定性读取，实际上下文显式进入 messages；补充背景有界，来源和未读部分可见。作者问答与 H2 改稿分别组装历史，聊天设想不自动成为故事事实。提案支持普通段落增删拆合，固定结构和选区外内容保留；完整差异、格式预览、实际汉字数与用量分别呈现。

采纳和撤销保存独立版本及编辑归因，不进入付费剧情/Slop 采纳路径。原始任务恢复重放冻结请求，继续打磨创建新回合。桌面与移动共用服务端会话。接口见[写作助手 API](../api/writing-assistant.md)，长期方向见[设计](../planning/writing-assistant.md)。

一期为保证恢复时不重新查询已变化的资料，每个回合冻结截至当前场景的只读资料池，再从中确定性查找。只有预算内实际选用的摘录进入模型，完整池只保存在本地服务数据库；长篇作品会增加每回合存储量。未来可在保持原请求和原读取结果可恢复的前提下，改为不可变版本引用。

## 故事级讨论与资料提案

工作台顶部“故事讨论”打开常驻面板，跨标签保留，窄屏使用单面板。故事级助手与正文助手分开：前者跟随故事和话题，面向角色及章节场景资料，不要求稿件；后者仍按稿件、分支、场景处理正文。故事话题支持新建、手动命名、最近话题选择和刷新恢复，在故事设定与大纲编排之间沿用同一话题。资料修改会作用于同一故事或所选大纲的使用者，界面须显示共享范围。

讨论任务只返回答复和整理建议。建议随本次回答产生，不单独调用模型；点击整理后才创建新任务，候选按角色、章节或场景持久化，保留字段前后值、来源和冻结基线。作者可手工编辑候选，再逐项采纳；新章及首批子场景为一个不可拆项。仅允许末尾追加或原位更新，不删除、重排现有章节场景。

未保存的候选编辑按故事和提案标识保存在当前 Workbench 内存中，折叠提案或切换话题、故事后仍可找回，原提案修订号同时保留以识别服务端新修订。整页刷新不保留这些未保存编辑；“保存候选”成功后才可从服务端恢复，不新增候选草稿的浏览器持久存储。

目标有未保存编辑时先完成保存或取消编辑，随后才整理或采纳。版本或目标内容不符时保留候选供比较，不覆盖新值；其他未冲突项目仍可处置。新增项不自动撤销；更新项仅当前目标仍等于采纳后快照时可撤销。处置不调用模型，写入原有角色卡与大纲实体后刷新对应页面。

上下文仅取当前故事、角色卡、所选单个大纲和话题讨论，不默认摄入正文。单任务至多两次模型业务调用、一次最多四项确定性只读查询；冻结请求、资料和结果以恢复，未知结果沿用原对账机制。故事讨论历史不进入 H2 正文编辑，资料采纳不自动成为 H2 计划、人物知情或 H1 正式事实。普通生成继续消费原资料，H2 生成仍由既有作者确认入口控制。

接口见[故事级助手 API](../api/story-assistant.md)，操作见[小说与大纲](../../user-doc/02-小说与大纲.md)。实施和验收状态只看[路线图](../roadmap.md)；工程检查不能代替真实模型与页面体验验收。
