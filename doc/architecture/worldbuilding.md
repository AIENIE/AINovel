# 世界草稿、版本与小说绑定

阶段状态以 [路线图](../roadmap.md) 为准。W2 将世界工作草稿与小说使用的内容分开。

## 数据与写入

- `worlds` 保留草稿基础信息、乐观锁 `revision`，增加 `draft_content_hash` 和原样保留的 `legacy_modules_json`。
- `world_entries` 保存稳定 UUID、世界、类型、标题、摘要、正文、别名、标签及可选旧模块/字段来源。
- `world_relations` 保存稳定 UUID、世界、起点/终点条目、关系类型和说明。删除草稿条目必须一并移除其关系。
- `world_versions` 保存完整 JSON 快照及 schema 所需固定字段、版次、来源、草稿 revision、内容摘要、说明、时间；只插入和读取，不修改或删除。
- `world_publish_receipts` 保存发布请求的幂等回执。没有内容变化的发布同样记录原请求，重复请求在后续草稿变化后仍返回原版本。
- 故事、大纲、稿件各增加 `world_version_id`、`world_binding_revision`。世界版本外键阻止引用悬空。

新增表完整结构及现有表增量见 V42；旧内容回填见 V43。所有草稿写入先锁世界记录并核对 revision；条目、关系、基础信息在一个事务中保存。旧模块接口仅适配条目来源映射；新条目与旧模块不维护两份可独立编辑的数据。

发布以服务器已保存草稿为准，允许空缺，不调用 AI。正式版本从第 1 版递增；编辑 revision 与发布版次不等价。后续草稿更改不会影响任何版本。删除世界仍受状态与已有快照限制。

## 迁移和差异

旧模块按字段迁移，已知字段映射到内置类型，未知字段和不规则模块保留为自由条目。原始模块字符串独立保存，防止格式、未知值或空值丢失。有效旧绑定及旧 active 世界建立第 0 号 `MIGRATION_BASELINE`，保留旧展示版本，不宣称恢复了历史；未绑定草稿不制造发布记录。

差异按条目/关系 UUID 对齐。改名属于修改，删除只改变新草稿和后续快照。比较覆盖基础信息、条目完整字段和关系，不依赖 AI 摘要。

## 绑定契约

新绑定在故事层选择正式发布版本。解析顺序：稿件显式覆盖、大纲显式覆盖、故事绑定。已有覆盖可以升级同世界版本或清除以继承；不新增下层独立绑定。失效的显式绑定显示待修复，不静默继承或读取最新草稿。

升级同时检查原版本 ID 和绑定 revision。故事升级仅影响继承者，其他小说和显式覆盖保持原版本。普通故事、大纲或稿件保存不能代替绑定操作。
