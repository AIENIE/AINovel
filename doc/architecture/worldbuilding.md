# 世界草稿、版本与小说绑定

阶段状态以 [路线图](../roadmap.md) 为准。W2 将世界工作草稿与小说使用的内容分开。

## 数据与写入

- `worlds` 保留草稿基础信息、乐观锁 `revision`，增加 `draft_content_hash` 和原样保留的 `legacy_modules_json`。
- `world_entries` 保存稳定 UUID、世界、类型、标题、摘要、正文、别名、标签及可选旧模块/字段来源。
- `world_relations` 保存稳定 UUID、世界、起点/终点条目、关系类型和说明。删除草稿条目必须一并移除其关系。
- `world_versions` 保存完整 JSON 快照及 schema 所需固定字段、版次、来源、草稿 revision、内容摘要、说明、时间；只插入和读取，不修改或删除。
- `world_publish_receipts` 保存发布请求的幂等回执。没有内容变化的发布同样记录原请求，重复请求在后续草稿变化后仍返回原版本。
- 故事、大纲、稿件各增加 `world_version_id`、`world_binding_revision`。世界版本外键阻止引用悬空。

新增表完整结构及现有表增量见 V42；旧内容回填见 V43；V44 将迁移基线摘要补齐为完整快照字节的 SHA-256，不改变快照内容。V45 从 Flyway 的 V43 执行时间恢复迁移基线的真实 UTC 时间，避免数据库会话时区造成偏移；不改变正式发布时间、快照字节或绑定。V42–V45 执行后原字节保持冻结。所有草稿写入先锁世界记录并核对 revision；条目、关系、基础信息在一个事务中保存。旧模块接口仅适配条目来源映射；新条目与旧模块不维护两份可独立编辑的数据。

发布以服务器已保存草稿为准，允许空缺，不调用 AI。正式版本从第 1 版递增；编辑 revision 与发布版次不等价。后续草稿更改不会影响任何版本。删除世界仍受状态与已有快照限制。

## 迁移和差异

旧模块按字段迁移，已知字段映射到内置类型，未知字段和不规则模块保留为自由条目。原始模块字符串独立保存，防止格式、未知值或空值丢失。有效旧绑定及旧 active 世界建立第 0 号 `MIGRATION_BASELINE`，保留旧展示版本，不宣称恢复了历史；未绑定草稿不制造发布记录。

差异按条目/关系 UUID 对齐。改名属于修改，删除只改变新草稿和后续快照。比较覆盖基础信息、条目完整字段和关系，不依赖 AI 摘要。

## 绑定契约

新绑定在故事层选择正式发布版本。解析顺序：稿件显式覆盖、大纲显式覆盖、故事绑定。已有覆盖可以升级同世界版本或清除以继承；不新增下层独立绑定。失效的显式绑定显示待修复，不静默继承或读取最新草稿。

升级同时检查原版本 ID 和绑定 revision。故事升级仅影响继承者，其他小说和显式覆盖保持原版本。普通故事、大纲或稿件保存不能代替绑定操作。

## 编辑和 AI

编辑器以条目目录和详情组织内容，支持类型、标签与关键词筛选；基础信息和历史快照分别展示。草稿保存保持 W1 的三方冲突合并、离页提醒和保存期间输入保护。发布确认显示空缺和完整差异；已发布快照只能查看。

单条补空要求正文为空，冻结整个世界内容基线并保留任务身份。模型输出先保存为任务结果，只有基线未变时才原子写入目标条目。W3 的单条精修结果进入持久提案库，作者采纳时原子保存对应目标；兼容精修接口只返回候选。空结果与过期候选不覆盖输入。新条目分别使用 `world.entry.generate` / `world.entry.refine`，默认未配置，报价明确返回 `AI_FEATURE_UNCONFIGURED`；旧迁移条目仍使用来源字段的独立配置。旧任务 schema 1 的指纹算法保持不变，W2 schema 2 覆盖条目、关系和兼容数据，W3 schema 3 另冻结完整渲染请求。缺失基线的旧任务停止恢复。

## 生成和向导

普通场景生成与写作助手通过 `WorldBindingService` 读取不可变快照。报价和任务受理保存 `Frozen`（含明确的未绑定状态），执行使用相同版本；场景恢复复用持久化的原始生成输入。结果自动保存前锁定并核对实际绑定，期间升级会交付 `NEEDS_REVIEW/WORLD_BINDING_CHANGED` 和保留的候选，不写入当前正文。H2 继续使用已有隔离上下文，不注入未分类世界条目。

向导确认世界候选只创建草稿。自动模式同样停在 `WORLD.awaitingPublication`，由作者预览、发布并绑定故事后才进入角色步骤。此确认没有 AI 调用；后续生成按剩余步骤重新报价。新大纲和稿件继承故事绑定。

## W3 数据基础

V46 增加 `worlds.overview`、`world_prompt_templates.action_templates_json` 和 `world_assistant_sessions/turns/proposals/receipts`。话题归属于独立世界；轮次保存冻结输入及分步请求与结果，提案保存候选和修订号，回执保证重复操作可重放。世界概览独立于来源条目，随新发布版本保存；旧快照不重写，空概览不改变原内容摘要。

世界模板的实际变量与帮助说明来自同一注册表；旧模块及字段精修模板保留，旧分模块整合要求用于概览。尚未实现的函数不执行，未知变量在调用前报错。


### W3 数据与任务约束

- `world_assistant_sessions`：世界及作者归属、话题标题、时间；按世界列出话题。
- `world_assistant_turns`：话题、幂等键/请求摘要、operation ID、冻结上下文 JSON、plan/final 请求与原始结果、实际补读及最终结果；分步结果单独提交，失败后仍可恢复。
- `world_assistant_proposals`：轮次、批次序号、目标类型、状态、候选 revision；`data_json` 保存动作、稳定目标 ID、fieldKey、before/modelCandidate/candidate、理由、来源及语义矛盾提示。候选编辑保留 modelCandidate，细化另建子提案。
- `world_assistant_receipts`：world/scope/request key 唯一回执；编辑、采纳及拒绝的并发重放保持同一结果。
- `worlds.overview` 独立于条目。`world_prompt_templates.action_templates_json` 保留新模板，不迁移或覆盖作者旧模板。

所有处置先锁世界，再锁话题/提案。采纳检查提案 revision、草稿 revision 和具体目标 before，原子写入目标、世界摘要/revision、提案状态与回执。其他目标变化需作者复核，不使整批候选全部不可用；概览使用完整来源摘要，来源变化则过期。

报价保存本次冻结的世界协作输入，任务直接使用获准输入，避免报价后模板变化改变实际请求。旧 W1/W2 补空 checkpoint 保留原 schema 与原提示；新 schema 3 同时保存每字段完整请求，重试不重新渲染模板。世界协作只读取当前世界和所选话题；小说正文及 H2 不参与。按需补读在第二步保留第一步已读材料，来源展示覆盖实际读取并集；报价的输入估算取实际冻结提示，不把其他话题的任务存储当作模型输入。

## W4 写作上下文基础

V47 增加两张表，历史世界快照及摘要不变：

- `world_context_preferences` 以 `(scope_key, world_id)` 为主键，保存作者 `user_id`、乐观锁 `revision`、核对版本 `reviewed_version_id`、来源选择 `choices_json`、核对内容摘要 `reviewed_hashes_json` 和 `updated_at`。目标为大纲或稿件场景，世界变更不串用偏好；保存先锁绑定资源，再检查版本和偏好 revision。
- `outline_ai_results` 保存 `id/outline_id/user_id/operation_id`、请求幂等键及摘要、动作、状态、revision、冻结输入、模型原结果、候选、处置回执和创建时间。大纲内请求键和 operation ID 各自唯一；大纲删除时级联清理结果。结果生成与原子追加分开，重复处置不得重复创建章节。

`world-context-v1` 只在一个绑定快照内执行本地匹配，按名称/别名、内容/标签及一跳关系排序。规则在同级候选中优先，同分按稳定 ID。手动排除高于自动命中，必选关系要求两端。默认完整概览和所有必选来源放不下时返回容量问题；自动来源按整项排除，不截断世界原文。H2 隔离结果不包含任何世界来源，排除清单仅供作者查看。
